Username/password lines created with create_line work perfectly. This problem is specific to activation codes.

*THE PROBLEM*

Activation codes created with create_activecode are born already expired, or already counting down. The app does not accept them because there is no pending activation left to perform.

Codes created manually in the panel are born in OnWatch state, meaning the duration starts when the customer first watches. Those work.

Both are package 7 (DEMO 1 HORA FULL), same reseller, same day. Every other field is identical. The only meaningful differences are exp_date, the missing batch, and the missing transaction ID.


*THE EXACT REQUEST I SEND*

POST to my reseller endpoint, content type application/x-www-form-urlencoded, with these fields:

api_key = (redacted)
action = create_activecode
package = 7
trial = 1
is_isplock = 0
code = 1849649048
reseller_notes = Demo customer name

The response is:
{"status":"STATUS_SUCCESS","data":{"id":54181}}

So the call reports success. The code is stored exactly as I submitted it and appears in get_activecodes, but with exp_date already set.

Since my group has force_batch_code = 1, and the codes that work carry a batch and a transaction ID, I assume the panel uses a batch creation path. create_activecodes, batch_create_activecode, create_batch_activecode, mass_activecode, create_mass_activecode, generate_activecodes, batch_activecode, create_activecode_batch, gen_activecode, generate_activecode, gen_activecodes, create_code, create_codes, gen_code, gen_codes, batch_code, batch_codes, create_batch, gen_batch, generate_batch, mass_trial, gen_mass_trial, generate_mass_trial, create_mass_trial, mass_trials, create_trial, gen_trial, gen_trials, get_batches, get_codes

In practice the response contains no code field at all. This is workable for me because I submit my own code and it gets stored, but the documentation should probably be corrected.
